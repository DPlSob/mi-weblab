Git / GitHub: guarda cada avance

Aprende a versionar tu web y a colaborar con cambios pequeños que se pueden explicar y revisar.

01. Dos herramientas, funciones distintas

Git

Sistema de control de versiones que funciona en tu ordenador. Guarda instantáneas, compara cambios y permite trabajar con ramas, incluso sin conexión.

GitHub

Plataforma que aloja repositorios Git y facilita la colaboración con issues, revisiones y pull requests. Necesitas conexión para publicar o descargar cambios.

Un commit guarda cambios en el repositorio local. Un push publica commits en el remoto: guardar un commit no lo sube automáticamente a GitHub.

02. Del archivo al repositorio remoto

  1. Archivos
  2. Staging
  3. Commit
  4. Repositorio local
  5. Push
  6. GitHub

Editas y guardas los archivos en el directorio de trabajo. git add prepara su estado actual en el área de staging. git commit registra una instantánea en tu historial local. git push envía los commits al repositorio de GitHub.

Si editas otra vez después de git add, debes volver a añadir el archivo para incluir también esos cambios. Revisa el staging antes de confirmar.

03. Prepara la versión v0.1

Instala Git y abre una terminal dentro de la carpeta weblab. Configura tu identidad solo si todavía no lo has hecho; usa tu nombre y un correo propio o el correo privado de GitHub.

git config --global user.name "Tu nombre"
git config --global user.email "tu-correo@example.com"
git init -b main
git status
git add .
git diff --staged
git commit -m "Crea WebLab v0.1: base del minicurso"
git tag -a v0.1 -m "Primera versión didáctica"

Crea un repositorio vacío en GitHub, sin README, licencia ni gitignore iniciales. Sustituye la URL de ejemplo por la del repositorio que has creado.

git remote add origin https://github.com/TU-USUARIO/weblab.git
git remote -v
git push -u origin main
git push origin v0.1

GitHub puede pedir autenticación mediante su gestor de credenciales o un token; la contraseña de la cuenta no sirve como contraseña de Git por HTTPS. El ZIP no contiene un historial Git: estos comandos crean el primer commit real.

04. Tu referencia de comandos

Comandos para consultar, guardar y compartir
ComandoQué hace
git init -b mainInicia un repositorio local con main como rama inicial.
git statusMuestra la rama y los cambios pendientes.
git diffCompara cambios de archivos seguidos que aún no están en staging.
git add html.htmlAñade el estado actual de ese archivo al staging.
git diff --stagedPermite revisar lo que entrará en el próximo commit.

git log --oneline --graph --allMuestra el historial y sus ramas de forma compacta.

Usa git clone cuando el repositorio ya existe en GitHub; entra después en la carpeta creada. No ejecutes git init otra vez dentro de un clon. Si pull --ff-only avisa de ramas divergentes, detente y revisa el historial con el docente.

05. Experimenta en una rama

Una rama permite desarrollar un cambio sin incorporarlo todavía a main. Guarda o revisa los cambios pendientes antes de cambiar de rama.

git switch -c mejora/menu
# Modifica el menú, guarda y comprueba las páginas.
git add index.html
git commit -m "Mejora el texto del menú de inicio"
git switch main
git merge mejora/menu

Ese ejemplo realiza un merge local. Para practicar revisión en GitHub, publica la rama con git push -u origin mejora/menu y abre un pull request hacia main antes de fusionar. Un compañero revisa el diff, comenta y comprueba el resultado. Después del merge remoto, cambia a main y actualiza con git pull --ff-only.

¿Qué ocurre con un conflicto?

Si dos ramas cambian las mismas líneas de forma incompatible, Git puede detener el merge. Abre los archivos que muestra git status, decide el contenido final y elimina los marcadores:

<<<<<<< HEAD
Texto en la rama actual
=======
Texto de la rama que se integra
>>>>>>> mejora/menu

Guarda la solución, comprueba la web y finaliza con git add archivo.html y git commit. Si prefieres cancelar un merge en curso para revisarlo después, usa git merge --abort. No elijas automáticamente una versión sin entender ambos cambios.

Para ampliar: documentación oficial de Git y guía oficial de pull requests.

Tu turno

Una pequeña práctica

Crea la rama mejora/objetivos, añade tus objetivos en HTML y guarda un commit. Publica la rama y abre un pull request hacia main.

En parejas, revisad el cambio y explicad qué aporta antes de fusionarlo.

Ver una pista
git switch -c mejora/objetivos
# Edita html.html, guarda y comprueba la página.
git status
git add html.html
git commit -m "Añade objetivos de aprendizaje en HTML"
git push -u origin mejora/objetivos

En GitHub, crea el pull request seleccionando main como base y mejora/objetivos como rama de comparación.
